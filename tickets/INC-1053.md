## INC-1053: Non-Compliant Device Access Block & Firewall Remediation

---

### Incident Summary

* **Incident ID:** NC-1053
* **Title:** Non-Compliant Device Access Block & Firewall Remediation
* **Environment:** Microsoft Intune, Microsoft Entra ID, Windows Defender Firewall
* **Impacted Components:** Device Compliance Policies, Microsoft Entra Conditional Access, Microsoft 365 Cloud Applications (Excel)

---

### Issue Description

User `jgarcia` on workstation `CLIENT08` experienced an access block preventing them from opening Microsoft Excel and other Microsoft 365 cloud applications. The workstation failed organizational security requirements due to the local Windows Firewall being disabled while explicitly mandated by the active Intune compliance policy (`Enterprise Compliance Baseline`), resulting in a **Non-Compliant** status.

---

### Root Cause Analysis (RCA)

1. **Compliance Baseline Mismatch:** The active Intune compliance policy (`Enterprise Compliance Baseline`) required the local Windows Firewall to be active (`Require`), but the setting was disabled on the client machine.
2. **Conditional Access Enforcement:** A Microsoft Entra Conditional Access policy was configured to grant access exclusively to compliant devices, successfully intercepting and blocking the user's authentication token request because the device reported a non-compliant state.

---

### Troubleshooting Steps Taken

* **Dashboard Verification:** Inspected the Intune admin center under device compliance monitoring and confirmed that `CLIENT08` under user `Jose Garcia` was explicitly flagged with a red **Not compliant** status.
* **Conditional Access Validation:** Reviewed Entra ID access controls and confirmed the enforcement of the compliance check blocking access to corporate cloud resources for non-compliant devices.

---

### Resolution & Implementation

1. **Remediate Local Security Settings:** Opened the Windows Defender Firewall settings as an administrator on `CLIENT08` and ensured the firewall was turned **On** for Domain, Private, and Public profiles to satisfy the compliance baseline policy requirements.
2. **Force MDM Synchronization:** Navigated to **Settings > Accounts > Access work or school** on the workstation, expanded the corporate account, clicked **Info**, and triggered a manual **Sync**.
3. **Verify Compliance Restoration:** Confirmed within the Intune admin center device compliance blade that `CLIENT08` successfully transitioned back to a **Compliant** status.
4. **Access Verification:** Verified that the strict Conditional Access block was automatically lifted, allowing `jgarcia` to successfully open and access Microsoft Excel and resume normal account operations.
